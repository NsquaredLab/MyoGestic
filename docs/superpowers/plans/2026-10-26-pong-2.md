# Pong 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Pong court you can read, a decoded command you can see, and a dummy synthetic wrist you steer with the arrow keys.

**Architecture:** Task 1 restyles `PongTask` (`myogestic/widgets/pong.py`) without touching its physics. Task 2 rebuilds the example-local cards in `examples/start_here/pong.py` around it and adds arrow-key drive for the dummy wrist.

**Tech Stack:** imgui-bundle, `myogestic.widgets` 2.0 kit.

**Spec:** the approved canvas https://claude.ai/artifact/1ALCTXxDNdjF5RpsURvCiM — its artboard sources are copied at `/private/tmp/claude-501/-Users-raul-code-myogestics-MyoGestic-main/c0763295-1de4-45ba-8e9d-ab0c5ea6bb02/scratchpad/design/pong2/project/*.dc.html` (Main = Play, Record, Simulated, Court). Read them for layout and copy; colours there are the app's own tokens.

## Global Constraints

- `docs/concepts/visual-language.md` § "The 2.0 kit" and CLAUDE.md apply: tokens only (no colour literals outside `_theme.py`/`common.py`), `ui_px` for fixed sizes, `display_font()` for the score, `mono_text` for values, `panel_header`, chips with `push_selected`/`pop_selected`.
- Physics (`Ball`, `_bounce`, `_track`, `_step`) and the `ui(command, target, effort)` contract stay as they are; new constructor arguments are keyword-only with backwards-compatible defaults, so `examples/panels/pong.py` keeps working unchanged.
- The training-block gauge stays **unsigned** (see `PongTask.ui`'s `effort` docstring): the signed command meter is drawn only when `target is None`.
- Keyboard: act only when the app window is focused and `imgui.get_io().want_text_input` is false; no global hooks.
- No AI attribution, no `Co-Authored-By`. Full suite once per task with `--deselect tests/test_recording_race.py::test_clear_after_detach_does_not_crash_acquire_loop`.

## Review Focus

- A participant typing an ID while Pong runs: Space and the arrows must not act.
- Velocity mode with a small bias: the meter shows the dead band so a resting command near zero reads as "nothing".
- Game over while predicting: the ball stops and nothing keeps scoring.
- Real hardware: no simulated card, arrows do nothing.
- 320 px cell at scale 2: score, meter and overlay buttons stay inside the court.
