## Code looks wrong: code unchanged

### C1. One target without claims disables orphan validation for every target

- Prose: `docs/concepts/controls.md:188`–`189` promises that ControlBus checks some target claims every alias and refuses an undriven control.
- Code: `myogestic/_controls_bus.py:223`–`241`, especially the early return at `233`–`234`, skips the entire check if even one target has no claims attribute.
- Headless reproduction: a ControlSet with aliases x and orphan, one target claiming only x, and another target whose send is a no-op and has no claims, constructs successfully. The same set with only the x-claiming target raises. This weakens the sensible documented guarantee; the guarantee was not rewritten to normalize the hole.

### C2. StatusBar displays an unsanitized participant path

- Prose: `docs/widget-gallery.md:58` says it shows the participant/session folder; `docs/concepts/file-names.md:20` describes the actual filename-safe ID.
- Code: `myogestic/widgets/panels/status_bar.py:76` constructs sessions_dir / ctx.participant directly. Actual saves use `participant_dir` at `myogestic/session/_core.py:432` and `_slug` at `240`.
- Example: ctx.participant = 'P 001' displays data/P 001, but the saved participant root is data/P-001. Slashes and an overlong ID can also disagree. The docs retain the sensible expectation that the storage readout describes actual storage.

## Unverified: claims retained

- **U1 — lock timing:** `docs/concepts/streams.md:75` and `docs/concepts/threading.md:46` quote roughly 1–5 microseconds per lock access. Locks exist in code, but no reproducible benchmark establishing that range was found.
- **U2 — external-library GIL/performance:** `docs/concepts/threading.md:29`–`39` and `67` describe NumPy/LSL/ImGui/OpenCV GIL release, most time being outside Python, and webcam interference. The Python call sites are visible; the third-party native behavior and workload-wide parallelism are not established by this repository. The gallery's 60-fps design target (`docs/widget-gallery.md:40`) was not benchmarked either. No external-source audit or performance profiling was performed.
- **U3 — classifier settling time:** `docs/concepts/edge-trigger.md:55`–`58` gives a typical 100–200 ms flicker interval. EdgeTrigger's call-count behavior is verified, but that physiological/model-dependent timing is not.
- **U4 — Zarr append benchmark:** `docs/concepts/recording.md:132` repeats approximately 1.5 ms per partial-chunk append. `myogestic/session/_core.py:62` records this as an earlier measurement, but it was not reproduced here.
- **U5 — GPU/memory and training-duration generalization:** `docs/concepts/threading.md:63` gives seconds-to-minutes training and implies the exclusive state rule prevents accidental GPU OOM. The exclusivity guard is verified; arbitrary user train/predict code, durations and CUDA memory use cannot be guaranteed by that guard.
- **U6 — detached-window macOS caveats:** `docs/concepts/widgets.md:146`–`147` warns about Retina sizing and native dialogs stacking with detached viewports. A main-window startup smoke is not a detached-window/native-dialog compatibility test.
- **U7 — suggested recording dose:** `docs/troubleshooting.md:40` recommends 6–10 clicks with approximately 3-second holds. These are operator recommendations, not code-enforced requirements or validated model-quality guarantees.
- **U8 — VHI jitter:** `docs/troubleshooting.md:166` cites 32–50 Hz and visible amplification of jitter. A typical example uses 32 Hz, but physical/remote VHI motion and the claimed effect were not exercised.
- **U9 — universal API-design assertions:** `docs/concepts/design-principles.md:14`–`17` says every public function is fully typed and the entire API fits one page. Exported objects and relevant signatures were inspected; no exhaustive typing proof or definition/measurement of one-page fit was available. These remain stated design goals.
